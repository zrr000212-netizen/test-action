# 阶段一：意图捕获（Intent Capture）

## 目标
理解用户想让技能完成什么任务、在什么场景下触发。

## 关键问题

在出方案前，先确认以下4个问题的答案：

1. **这个技能要解决什么问题？**
2. **用户在什么情况下会说"用这个技能"？（触发词/场景）**
3. **技能完成后，期望的输出格式是什么？**
4. **技能的使用频率和重要性如何？**

## 访谈技巧

- 如果对话中已有现成工作流，先提取再提问
- 主动询问边界情况、异常处理
- 遇到模糊需求，用具体例子帮助澄清
- **不等用户催促，主动出方案**

## 方案模板

```markdown
【意图捕获方案】

技能名称建议：<name>
技能定位：<what it does>
预期触发场景：
  - 触发词/短语：<phrases>
  - 上下文：<contexts>
预期输出：<output format>
验证方式：<how to verify it works>

请胖教练确认上述理解是否准确，有无补充或修正？
```

## 示例

**好的方案：**
```
技能名称建议：doc-writer
技能定位：将技术文档草稿按指定风格指南润色优化
预期触发场景：
  - 触发词："润色这个文档"、"按中文风格指南优化"、"帮我改一下这个文档"
  - 上下文：用户提供了文档内容，需要按规范改写
预期输出：优化后的完整文档，附带修改说明
验证方式：对比原文与优化后版本，确认符合风格指南
```

**不好的方案（信息不足）：**
```
技能名称建议：doc-writer
技能定位：写文档
预期触发场景：用户想写文档时
```

## 注意事项

- 名称建议用 kebab-case（如 `doc-writer`、`backup-skill`）
- 触发场景要包含多种表述方式（正式/非正式、完整/缩写）
- 如果涉及多 Agent，确保明确各 Agent 的角色分工
